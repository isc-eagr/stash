# Scene Releases remediation plan

Implement audit items 1–9, 11–12, 14, and 16. Exclude export/import (10), the unrelated unfinished release API capabilities (13), and plugin lifecycle hooks (15). New schema fields needed for preservation and playback remain in scope. Keep changes in `_custom` files or mark inline upstream edits per `CUSTOM_CODE_CONVENTIONS.md`. Do not run production deployment or start the app without explicit instruction.

## Product decisions

- Releases independently own ratings, performers, tags, groups, custom fields, markers, and viewing/O-history.
- The release editor exposes all preserved metadata. Existing incomplete releases restore only their known data; never copy parent metadata to fill gaps.
- Parent scene cards and ordinary filters represent main-scene metadata, while effective date, release count, and combined galleries include releases.
- Library-wide history includes each release event once and attributes it to that release's performers.
- When a source scene already has releases, conversion moves them directly to the target. Extracting the source release later leaves its former children under the target.

## Storage and conversion

1. Add standalone upgrade SQL and extend the fresh-install `scene_releases.up.sql`: release-owned rating/organized/progress fields, ordered URLs, performers, tags, groups with indices, Stash IDs, custom fields, provenance, and a real `cover_blob` foreign key to blobs. Existing release metadata remains unchanged; never infer missing historical metadata from the parent. Report dangling cover checksums and repair only when original bytes exist.
2. Extend generic rating-score ownership with `scene_release`, including criteria, bonuses, penalties, labels, raw/weighted values, and timestamps. Preserve the stored rating on conversion without recalculation or duplicate O bonuses. Later rating edits use the release's own cast, markers, and history.
3. Add nullable `release_id` ownership to markers, negative markers, loop presets, scene viewing events, and scene O-events. Retain marker IDs and all related tags, performer roles, playlist references, event duplicates, video timestamps, loop state, and timestamps. Ordinary scene queries explicitly restrict these records to `release_id IS NULL`; release queries select by release ID. Global totals include both owners once. Give loop-preset names owner-specific uniqueness.
4. Build a transaction-scoped conversion service used by both GraphQL resolvers. Capture the complete source record—descriptive fields, date precision, relationships, rating rows, cover bytes/reference, all files and primary selection, activity, custom fields, and metadata timestamps—before deleting it. Scene-to-release transfers that record to the release, moves existing source releases flat to the target, and leaves target-main data alone. Release-to-scene restores only the selected release's current data and activity, leaving parent and sibling data alone. Failures roll back the whole operation. Add persisted request IDs to make retries idempotent.
5. Retire the two conversion dialogs' marker/O-history transfer checkboxes. Omitted/false legacy API flags use lossless ownership transfer; explicit true returns a validation error before changes. Update dialog copy and show the source/target and affected file/activity counts.
6. Protect covers during transfer: attach the destination reference before releasing the source reference. Ensure a full release update never writes an unpopulated `cover_blob` to null. Release deletion and replacement clean up only unreferenced blobs. Provide explicit cover removal.

## Files, player, and UI

7. Make create-from-files and add-file use one move operation within a scene family. Prevent new duplicate main/release or sibling-release ownership and reject silent steals from another family. Preserve legacy cross-family references. A non-destructive removal moves the file back to the parent. Before physical deletion, check every main/release reference; use the existing transactional file deletion/trash service and report cleanup failures accurately. Parent-scene deletion includes all release files and generated assets.
8. Enforce one designated primary when an owner has files. Preserve it during conversions; first attachment to an empty owner becomes primary. On removal, select the lowest remaining file ID. On release deletion, return the former release primary when the main owner was empty. Validate primary selection and sort primary first, then file ID. Streams and preview paths use the designated primary.
9. Replace the player's scene-object file/stream substitution with an explicit main-scene/release playback context. Scope poster, thumbnails, captions, funscript, heatmap, markers, negative markers, loop presets, resume position, watch/O writes, and generated previews to the selected owner. Reset media state by owner and primary file; save outgoing progress before switching and reject late callbacks for the wrong owner. Use a validated `release` route query parameter so marker/playlist links select the right owner before seeking. Missing release assets do not use parent assets. Preserve out-of-range stored timestamps while preventing invalid seek actions.
10. Extend release GraphQL fields/inputs for the full editor, rating scores, owner-scoped activity, ordered URLs, cover removal, and primary-file identity. Omitted input means unchanged; null/empty input intentionally clears supported fields. `urls` wins when supplied; legacy `url` edits only its first entry. Keep ordinary scene-list queries compact.
11. Reuse scene edit controls for release metadata/rating editing. Track dirty values, validate fields, support cancel/navigation prompts and cover replace/remove. Rework the Releases panel into compact thumbnail/metadata summaries with accessible expanders, standard action menus, localized copy, shared confirmations, and responsive long-text layout. Show the selected release next to the player. Remove native confirm dialogs and misleading preservation claims.
12. Centralize cache invalidation for changed scenes, releases, files, ratings, histories, galleries, effective dates, counts, and filtered lists. Clear invalid active-release selections and refresh versioned cover URLs.
13. Replace effective-date sentinel SQL with one null-preserving expression shared by filters and sort. All-undated scenes return null. Combined galleries are the distinct union of direct and release galleries in scene display, reverse gallery navigation, criteria, and counts; `direct_galleries` remains main-only.

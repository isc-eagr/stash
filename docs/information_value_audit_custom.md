# Information value audit

Date: 2026-10-01. Scope: Scenes catalog (cards, list, sorts), scene detail, Vatos catalog, vato detail, O Stats, Scene Stats, and Vato Stats.

The largest opportunities are clearer metric definitions and filter scope, followed by reducing repeated summaries and moving secondary information behind disclosure. Useful distinctions should survive the cleanup: partners versus scenes versus time, personal O events versus on-video orgasms, and numeric ratings versus metallic tiers.

This audits the current working tree, including pre-existing uncommitted performer-card and scene-overview edits. No application code was changed. Implementation review covered the catalog controls, detail tabs and their supporting panels, and dashboard/chart helpers. Browser checks used the dev UI on port 3010 with GraphQL configured for port 9998 and the testing configuration. The fixture contains 13 scenes and 30 vatos; observations establish behavior, not usage frequency or performance in a large library. The browser's default narrow viewport also exposed horizontal scrolling in tables. Populated states for every detail tab and a full desktop/mobile layout matrix were not exercised.

**Priorities:** P1 = can cause a mistaken interpretation; P2 = slows a common task or obscures useful information; P3 = smaller, contextual cleanup. These are information-design priorities, not assertions that every item is a software defect. The report combines browser observations with implementation review. Conditional branches not exercised in the fixture are identified where relevant. Recommendations are design judgments, not usability-test findings.

## What to preserve

- Exact counts, durations, role evidence, and sample sizes in expanded views; they provide value when comparing or checking annotations.
- Active-sort highlights and temporary metric columns, provided the displayed value uses the sort's actual unit.
- Unknown badges for genuinely missing data, rating criteria's per-criterion sample counts, and existing explanations for overlapping demographic/age credit.
- O Stats' note that an O is credited to every vato in its scene. Those percentages are overlapping event associations, not a partition or direct attribution to one vato.
- Conditional empty-section hiding, lazy tab loading, marker selection summaries, scope-preserving navigation, and precise timestamp links.
- Existing separation of File Info, History, Releases, and editing operations; improve their navigation hierarchy without mixing maintenance details into browsing summaries.

## Recommended first change

Start with SS1/SS2 and SL1: distinguish zero/missing values and make scene date labels/sorting agree. These are small, independently reviewable corrections. Then address dashboard scope (SS3, VS2, OS1) before changing card density. Add focused bucket/filter tests when implementing those behavior changes; this audit itself adds no runtime behavior.
